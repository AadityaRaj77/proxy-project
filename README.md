# Custom Network Proxy Server

ACM IIT Roorkee Open Project

## Overview

This project implements a **custom forward HTTP/HTTPS proxy server** using low-level TCP sockets in Python.  
The proxy sits between a client and destination servers, intercepting requests, enforcing access control, and forwarding traffic transparently. The primary goal of this project is to gain a practical understanding of **network programming**, **HTTP/1.1 behavior**, **HTTPS CONNECT tunneling**, and **proxy server design**, without relying on high-level proxy frameworks.

## Features

- Built using **raw TCP sockets** (`socket`, `bind`, `listen`, `accept`, `recv`, `send`)
- Handles standard **HTTP requests** (GET, HEAD, POST, etc.)
- Supports **HTTPS traffic via CONNECT tunneling** (blind TLS forwarding)
- Concurrent client handling using a **thread pool** (`ThreadPoolExecutor`)
- **Domain and IP-based request filtering**
  - Exact domain match
  - Subdomain / suffix match (e.g. `.example.com`)
  - Direct IP blocking
- **Consistent filtering for both HTTP and HTTPS (CONNECT)**
- **O(1) blacklist lookups** using a hash set for efficient filtering
- Transparent forwarding of origin server responses
- **Clear logging that distinguishes proxy-side blocking from origin-side responses**
- Structured logging using **rotating log files**
- Configurable via command-line arguments and config files

## How It Works

### HTTP Requests

1. Client sends an HTTP request to the proxy.
2. Proxy reads and parses the request line and headers.
3. The destination host is checked against the blocklist.
4. If blocked, the proxy returns **`403 Forbidden`** immediately.
5. If allowed:
   - Proxy connects to the origin server.
   - Forwards the request (absolute URLs are converted to relative paths).
   - Relays the origin server’s response back to the client.

### HTTPS Requests (CONNECT)

1. Client sends a `CONNECT host:port` request.
2. Proxy checks the destination against the blocklist.
3. If blocked, the proxy rejects the request with **`403 Forbidden`**.
4. If allowed:
   - Proxy responds with:
     ```
     HTTP/1.1 200 Connection Established
     ```
   - A transparent TCP tunnel is created.
5. TLS handshake and encrypted traffic pass through the proxy unchanged.

> The proxy does **not** decrypt HTTPS traffic, it only forwards encrypted bytes.

## Configuration

### Blocked Domains

Edit `config/blocked_domains.txt`:

Rules:

- Exact domain match (e.g. `badsite.org`)
- Subdomain / suffix match (e.g. `.example.com`)
- Direct IP blocking
- Comment lines start with `#`

Blocking is enforced for both **HTTP** and **HTTPS (CONNECT)** requests.

## Running the Proxy

### Requirements

- Python 3.9+
- Windows / Linux / macOS

### Start the proxy

```bash
python src/proxy.py --host 127.0.0.1 --port 8888 --workers 20 --blocklist config/blocked_domains.txt --log logs/proxy.log

```

## Testing

### HTTP via proxy

```bash
curl.exe -x http://127.0.0.1:8888 http://example.com -I
```

### HTTPS via proxy

```bash
curl.exe -x http://127.0.0.1:8888 https://example.com -I
```

### Expected Behavior

- Blocked domains

  - HTTP → 403 Forbidden (generated by proxy)
  - HTTPS → CONNECT rejected with 403 Forbidden

- Allowed domains

  - Requests are forwarded to the origin server
  - Origin server response is returned transparently

- HTTPS connections show 200 Connection Established before TLS traffic

### Logging

All requests are logged with:

- client IP and port
- destination host and port
- request method and path
- proxy decision (ALLOWED / BLOCKED)
- origin server HTTP status code (for allowed requests)
- total bytes transferred

Example:

```bash
127.0.0.1:50877 -> ph.com:80 ALLOWED HEAD / ORIGIN_STATUS=403 BYTES=255
```
